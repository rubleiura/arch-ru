# 🐧 Упрощённая установка Arch Linux: Макет блочной установки

> 📘 **Философия проекта:** Архитектура «копируй-понимай-выполняй». Вместо слепого следования wiki, вы получаете готовую структуру команд с подробными комментариями, которую можно визуально редактировать, анализировать и безопасно запускать по блокам.

**Состав репозитория:** 6 макетов установки (два семейства загрузочных стеков) + 1 пост-установочный чек-лист + этот README.

**Актуальность:** редакции макетов от `2026-10-08`, проверены на `mkinitcpio 42.2` / `linux-lts 6.18.55`. История правок каждой редакции — в шапке соответствующего `.txt`-файла.

---

## 🚀 Быстрый старт: Получение репозитория

> ⚡ **Это первый шаг для любого способа установки!**

```bash
git clone https://github.com/rubleiura/arch-ru && cd arch-ru
```

📌 **Что это делает:**
- Скачивает все макеты установки (`.txt` файлы) в папку `arch-ru` и переходит в неё.

> 💡 **Совет:** Выполните эту команду сразу после загрузки в Live-среду, чтобы все файлы были под рукой. `git` есть и в официальном Arch ISO, и в live-образах EndeavourOS/Garuda.

## 🛑 КРИТИЧЕСКОЕ ПРЕДУПРЕЖДЕНИЕ О БЕЗОПАСНОСТИ

- ⚠️ **Все макеты выполняют ПОЛНУЮ ОЧИСТКУ ВЫБРАННОГО ДИСКА** (`wipefs --all`, `sgdisk -Z`).
- 🔒 Перед началом **обязательно создайте резервную копию** всех важных данных на внешний носитель или облако.
- 🔍 Всегда дважды проверяйте переменную `sdx` (имя диска) перед выполнением блоков разметки.
- 🚫 Дуал-бут макетами не поддерживается: диск затирается целиком, включая чужой ESP.
- 📜 Автор не несёт ответственности за потерю данных в результате неверного следования инструкции.

## 🔄 Два способа выполнения установки

Проект поддерживает два рабочих сценария. Выберите тот, который лучше подходит под ваше оборудование и уровень комфорта.

| Критерий | 🌐 Способ 1: Удалённо через SSH | 💻 Способ 2: Локально в графической Live-среде |
|:---|:---|:---|
| **Оборудование** | 2 компьютера (управляющий + целевой) | 1 компьютер |
| **Загрузочный носитель** | Официальный Arch Linux Live ISO | EndeavourOS, Garuda Linux или любой Arch-based ISO с GUI |
| **Редактирование макета** | В графическом редакторе управляющего ПК | Встроенный редактор Live-среды (`mousepad`, `kate`, `gedit`) |
| **Удобство для новичков** | ⚙️ Требует базовых знаний сети/SSH | ✅ **Рекомендуется**: всё в одном окне, нет настройки сети |
| **Когда выбирать** | Установка на сервер, минималистичный ПК или несколько машин | Классическая установка на домашний ПК/ноутбук |

📌 **Вставка больших блоков.** Тяжёлые блоки помечены в макетах окном «ОБЪЁМ БЛОКА N: X КБ ВСТАВКИ». Пока выполняется «тяжёлая» команда (`pacman`, `mkinitcpio`, `mkfs.btrfs`), занятая ВМ может не принять весь вставленный текст — хвост блока теряется. Вставляйте такой блок частями, от одной границы `# #-----` до следующей, и только после завершения предыдущей команды. SSH-сессия надёжнее всего.

<details>
<summary>📋 <b>Инструкция по подготовке среды (нажмите, чтобы раскрыть)</b></summary>

### 🌐 Способ 1: SSH (2 компьютера)
1. Загрузите **целевой** компьютер в Arch Linux Live.
2. В терминале Live-среды выполните:
   ```bash
   pacman -Sy --noconfirm openssh && systemctl start sshd
   passwd root
   ip a  # запишите IP-адрес
   ```
   > 💡 Если ISO давно скачан и `pacman` ругается на ключи, сначала обновите keyring: `pacman -Sy --noconfirm archlinux-keyring`.
3. На **управляющем** компьютере: `ssh root@<IP_целевой>`
4. **Выполните команду быстрого старта** (если не сделали ранее):
   ```bash
   git clone https://github.com/rubleiura/arch-ru && cd arch-ru
   ```
5. Откройте `.txt` файлы в редакторе на управляющем ПК, выполните замену переменных и копируйте блоки в SSH-сессию.

### 💻 Способ 2: Локальный (1 компьютер) — РЕКОМЕНДУЕТСЯ ДЛЯ НОВИЧКОВ
1. Запишите образ **EndeavourOS** или **Garuda Linux** на USB (Ventoy/BalenaEtcher).
2. Загрузите компьютер с флешки в графический режим.
3. **Сразу выполните команду быстрого старта:**
   ```bash
   git clone https://github.com/rubleiura/arch-ru && cd arch-ru
   ```
4. Откройте нужный `.txt` файл через `mousepad`, `kate` или `gedit`.
5. Разместите окна: слева — редактор, справа — терминал. Копируйте блоки команд мышью и вставляйте в терминал.

## 🧭 Выбор макета установки

| Файл макета | Прошивка | Загрузчик | Шифрование | LVM | Swap | Secure Boot |
|:---|:---|:---|:---|:---|:---|:---|
| `Arch UEFI.txt` | UEFI (GPT) | GRUB + grub-btrfs | ❌ | ❌ | раздел на диске + zram | ❌ |
| `Arch BIOS.txt` | BIOS/Legacy (GPT) | GRUB + grub-btrfs | ❌ | ❌ | раздел на диске + zram | ❌ |
| `BTRFS  LVM  LUKS UEFI.txt` | UEFI (GPT) | GRUB + grub-btrfs | ✅ LUKS2 | ✅ | том LVM + zram | ❌ |
| `BTRFS  LVM  LUKS BIOS.txt` | BIOS/Legacy (GPT) | GRUB + grub-btrfs | ✅ LUKS2 | ✅ | том LVM + zram | ❌ |
| `BTRFS  UKI Secure Boot UEFI.txt` | UEFI (GPT) | systemd-boot + UKI | ❌ | ❌ | только zram | ✅ sbctl |
| `BTRFS LUKS2 UKI  SecureBoot UEFI.txt` | UEFI (GPT) | systemd-boot + UKI | ✅ LUKS2 | ❌ | только zram | ✅ sbctl |
| `POST-INSTALL Arch Linux.txt` | любая | любой | любое | любое | — | — |

**Кому какой:**

- `Arch UEFI.txt` — **лучший старт для новичков**: современное оборудование, минимум шагов.
- `Arch BIOS.txt` — старые ПК и legacy-загрузка; нужен раздел BIOS Boot (`ef02`).
- `BTRFS  LVM  LUKS UEFI.txt` и `BTRFS  LVM  LUKS BIOS.txt` — максимальная безопасность на GRUB: пароль при каждой загрузке, гибкое управление томами, есть гибернация. BIOS-редакция требует отдельный незашифрованный `/boot` (ext4).
- `BTRFS  UKI Secure Boot UEFI.txt` — 🔐 проверяемая цепочка загрузки: systemd-boot + единый образ ядра (UKI), свои ключи Secure Boot через `sbctl`.
- `BTRFS LUKS2 UKI  SecureBoot UEFI.txt` — 🔐 максимум защиты: шифрованный корень + Secure Boot. Дополнительно: обязательный шаг `cryptsetup luksHeaderBackup` на внешний носитель в `БЛОКЕ 20` и `БЛОК 19` аварийного восстановления с live-ISO.
- `POST-INSTALL Arch Linux.txt` — 📦 выполняется **строго после** первой загрузки в новую систему.

> 🔀 **Два семейства макетов.** Файлы `Arch …` и `BTRFS  LVM  LUKS …` построены на **GRUB** и используют реальный swap-раздел/том (возможен гибернационный сценарий через `resume=UUID=…`). Файлы `BTRFS … UKI …` построены на **systemd-boot + UKI** и **sbctl**, swap у них целиком в zram, гибернации нет. Это не версии одного макета, а разные загрузочные стеки: GRUB проще, UKI + Secure Boot — проверяемая цепочка загрузки и подписанные параметры ядра.
>
> ⚠️ **Secure Boot и GRUB.** GRUB из Arch не подписан, а его модули грузятся с диска непроверяемыми, поэтому GRUB-макеты Secure Boot **не поддерживают**: перед установкой выключите его и в прошивке, и в настройках ВМ (иначе неподписанный загрузчик не запустится, а ISO может быть отклонён с «Access denied»). Нужен Secure Boot — берите UKI-макет.
>
> 💡 **Совет для начинающих:** если не уверены, какой тип прошивки у вас, начните с `Arch UEFI.txt` или `Arch BIOS.txt`. Макеты с LUKS сложнее в восстановлении и требуют запоминания пароля.

Во всех макетах корень — Btrfs с подтомами `@`, `@home`, `@log`, `@pkg`, ядро — `linux-lts`, снимки — `snapper` + `snap-pac` + `btrfs-assistant`.

## 🗺️ Схема разделов по макетам

| Файл | `sda1` | `sda2` | `sda3` |
|:---|:---|:---|:---|
| `Arch UEFI.txt` | ESP, 1024 МБ (`ef00`) | Root Btrfs (`8300`) | Swap, 4G (`8200`) |
| `Arch BIOS.txt` | BIOS Boot, 4 МБ (`ef02`) | Root Btrfs (`8300`) | Swap, 4G (`8200`) |
| `BTRFS  LVM  LUKS UEFI.txt` | ESP, 1024 МБ (`ef00`) | LUKS2 → LVM, всё место | — |
| `BTRFS  LVM  LUKS BIOS.txt` | BIOS Boot, 4 МБ (`ef02`) | `/boot`, ext4, 1 ГБ | LUKS2 → LVM, всё место (`8309`) |
| `BTRFS  UKI Secure Boot UEFI.txt` | ESP, 1024 МБ (`ef00`) | Root Btrfs, всё место | — |
| `BTRFS LUKS2 UKI  SecureBoot UEFI.txt` | ESP, 1024 МБ (`ef00`) | LUKS2 → Root Btrfs, всё место (`8309`) | — |

> 📏 **Запас места на ESP.** 1024 МБ хватает для штатного набора. Если планируете держать несколько ядер и старые снимки (а в UKI-макетах на ESP живут сам UKI-образ, а после `БЛОКА 13A` ещё и `vmlinuz` с `initramfs` для записей-снимков), увеличьте раздел до 2048 МБ: в `БЛОКЕ 5` замените `-n 1::+1024M` на `-n 1::+2048M`, а размер root-раздела пересчитайте.

## 📋 Пошаговая настройка переменных (КРИТИЧЕСКИ ВАЖНО)

В макетах используется **трёхэтапная замена переменных**. Не пытайтесь заменить всё сразу! Следуйте строгой последовательности, чтобы избежать ошибок разметки.

### 🔹 ЭТАП 1: `[EDIT] БЛОК 1` — Локализация зеркал
*Выполняется ПЕРЕД любыми действиями.*
1. Запустите `🔍 [LIVE] БЛОК 0` — скрипт определит географию по IP (`ipapi.co`, при неудаче `ipinfo.io`) и предложит 10 ближайших стран.
2. Скопируйте полученный список стран (например, `Russia,Estonia,Finland...`).
3. В `БЛОК 1` замените значение `Russia` на ваш список:
   ```
   Местоположение пользователя # Russia,Estonia,Finland,Latvia,Lithuania
   ```

### 🔹 ЭТАП 2: `[EDIT] БЛОК 4` — Основные переменные системы
*Выполняется ДО разметки диска.* Используйте функцию **«Найти и заменить везде»** в графическом редакторе:

| Токен | Пример значения | Что это значит? | ⚠️ Важно |
|:---|:---|:---|:---|
| `sdx` | `nvme0n1` или `sda` | Имя **физического** диска | Узнайте через `lsblk`. Без цифр и без `/dev/`! |
| `Sony` | `arch-pc` | Имя компьютера (hostname) | Только латиница, без пробелов |
| `forename` | `ivanov` | Логин пользователя | Только латиница, без пробелов |
| `User Name` | `Игорь Иванов` | Полное имя пользователя | Можно кириллицу и пробелы |
| `amd-ucode` | `intel-ucode iucode-tool` | Микрокод CPU | Заменяйте **только** на Intel; для AMD оставьте как есть |
| `linux-lts` | `linux` | Ядро | Можно оставить LTS (рекомендуется) или заменить на основное |
| `defaults` | `ssd,noatime,…` | Параметры монтирования Btrfs | Значение подскажет `БЛОК 3` (см. ниже) |
| `bgrt` | `spinner`, `arch-glow` | Тема plymouth | Список тем: `plymouth-set-default-theme -l` |
| `4G` | `8G`, `16G` | Размер swap-раздела/тома | **Только GRUB-ветка.** Для гибернации — не меньше объёма RAM. В UKI-макетах токена нет (swap только в zram, размер `ram / 2`) |
| `Grub Arch Linux` | `Grub` | `--bootloader-id` GRUB | **Только UEFI-редакции GRUB-ветки** (имя записи в меню прошивки) |
| `cryptroot` | `crypt` | Имя LUKS-контейнера | **Только `BTRFS LUKS2 UKI  SecureBoot UEFI.txt`** |

**Опции монтирования Btrfs из `БЛОКА 3`** (подставьте вместо токена `defaults`):

| Тип диска | Значение |
|:---|:---|
| SSD | `ssd,noatime,space_cache=v2,compress=zstd:3,discard=async` |
| HDD | `noatime,space_cache=v2,compress=zstd:3,autodefrag` |

> 📌 **Где именно заменяется `defaults`:** в `Arch UEFI.txt` и `Arch BIOS.txt` — в `БЛОКЕ 7`; в `BTRFS  LVM  LUKS …` — в `БЛОКЕ 7F`; в `BTRFS  UKI Secure Boot UEFI.txt` — в `БЛОКЕ 7A`; в `BTRFS LUKS2 UKI  SecureBoot UEFI.txt` — в `БЛОКЕ 7C`.
> 📌 В LVM-редакциях в командах также встречается имя контейнера `cryptlvm` — его таблица `БЛОКА 4` не перечисляет; менять его не обязательно, но если меняете, то везде и согласованно с `rd.luks.name=…`.

### 🔹 ЭТАП 3: `[EDIT] БЛОК 6` — Точные имена разделов
*Выполняется СТРОГО ПОСЛЕ выполнения `БЛОК 5` (разметки)!*
1. Скопируйте и выполните `💾 [LIVE] БЛОК 5`. Он создаст разделы и выведет `fdisk -l` и `lsblk`.
2. Посмотрите на реальные имена разделов в терминале (например, `nvme0n1p1`, `nvme0n1p2`).
3. Вернитесь в редактор и в `БЛОК 6` замените шаблоны — по схеме своего макета:

| Макет | `sda1` | `sda2` | `sda3` |
|:---|:---|:---|:---|
| `Arch UEFI.txt` | ESP | Root | Swap |
| `Arch BIOS.txt` | BIOS Boot | Root | Swap |
| `BTRFS  LVM  LUKS UEFI.txt` | ESP | LUKS/LVM | — |
| `BTRFS  LVM  LUKS BIOS.txt` | BIOS Boot | `/boot` (ext4) | LUKS/LVM |
| `BTRFS  UKI Secure Boot UEFI.txt` | ESP | Root | — |
| `BTRFS LUKS2 UKI  SecureBoot UEFI.txt` | ESP | Root (LUKS2) | — |

> 📌 **Правило безопасности:** Не заменяйте `sda1/sda2/sda3` до выполнения Блока 5! Ошибка здесь приведёт к форматированию несуществующих разделов и остановке установки.

## 🚀 Пошаговый процесс установки

После корректной замены переменных в Блоках 1, 4 и 6 выполняйте макет строго по порядку. Нумерация в двух семействах различается.

### 🅰️ GRUB-ветка (`Arch UEFI.txt`, `Arch BIOS.txt`, `BTRFS  LVM  LUKS UEFI.txt`, `BTRFS  LVM  LUKS BIOS.txt`)

|:---|:---|:---|:---|
| 0️⃣ | `[LIVE] БЛОК 0` | Live-среда | Определяет географию для зеркал |
| 1️⃣ | `[EDIT] БЛОК 1` | Редактор | **Замена страны** (см. выше) |
| 2️⃣ | `[LIVE] БЛОК 2` | Live-среда | Раскладка и шрифт консоли, NTP, `locale-gen`, настройки `pacman` и `reflector` |
| 3️⃣ | `[LIVE] БЛОК 3` | Live-среда | Диагностика оборудования: `lsblk`, CPU, плата, тип дисков → опции Btrfs |
| 4️⃣ | `[EDIT] БЛОК 4` | Редактор | **Замена основных переменных** |
| 5️⃣ | `[LIVE] БЛОК 5` | Live-среда | Очистка и разметка диска (`wipefs`, `sgdisk`), вывод `fdisk`/`lsblk` |

| 1️⃣2️⃣ | `[CHROOT] БЛОК 12` | chroot | `linux-lts`, GRUB + grub-btrfs, HOOKS/MODULES **mkinitcpio**, plymouth, `resume=UUID=…`, `grub-mkconfig`, `mkinitcpio -P` |
| 1️⃣3️⃣ | `[CHROOT] БЛОК 13` | chroot | snapper + snap-pac + btrfs-assistant, flatpak, утилиты, zram + earlyoom, nftables, Bluetooth/печать/сканеры, шрифты, базовый софт |
| 1️⃣4️⃣ | `[CHROOT] БЛОК 14` | chroot | Видеодрайверы и Wayland (4 сценария) |
| 1️⃣5️⃣ | `[CHROOT] БЛОК 15` | chroot | Гостевые дополнения VirtualBox (только если установка в ВМ) |
| 1️⃣6️⃣ | `[CHROOT] БЛОК 16` | chroot | Окружение рабочего стола; в конце — `exit` из chroot |
| 🏁 | `[LIVE] БЛОК 17` | Live-среда | Удаление ключей SSH live-сессии, `swapoff`, размонтирование, `poweroff` |

### 🅱️ UKI-ветка (`BTRFS  UKI Secure Boot UEFI.txt`, `BTRFS LUKS2 UKI  SecureBoot UEFI.txt`)

Блоки `0`–`6`, `8`–`11`, `13`–`16` — те же по назначению. Отличия:

| Блок | Где выполняется | Что делает |
|:---|:---|:---|
| `[LIVE] БЛОК 7` (+ `7A`) | Live-среда | Форматирование ESP, подтома Btrfs, монтирование. В шифрованной редакции — `7A` открытие контейнера, `7B` Btrfs внутри контейнера, `7C` монтирование |
| `[CHROOT] БЛОК 12` | chroot | `linux-lts`, **systemd-boot** (`bootctl install`), сборка **UKI** через `systemd-ukify`, `/etc/kernel/cmdline` как единственный источник параметров ядра, пресет mkinitcpio с `default_uki=`, plymouth |
| `[CHROOT] БЛОК 13A` | chroot | Снимки Btrfs в меню systemd-boot (замена grub-btrfs) |
| `[СИСТЕМА] БЛОК 13B` | Уже в системе | Возврат дерева снимков после отката через btrfs-assistant |
| `[CHROOT] БЛОК 17` | chroot | 🔐 **Активация Secure Boot:** финальная пересборка → `sbctl create-keys` → `sbctl enroll-keys -m` → подписи |
| `[LIVE] БЛОК 18` | Live-среда | Завершение установки: очистка ключей live-сессии, размонтирование, выключение |
| `[LIVE-ISO] БЛОК 19` | Live-среда | 🚑 Аварийное восстановление — **есть только в шифрованной редакции и при установке ПРОПУСКАЕТСЯ** |
| `[СИСТЕМА] БЛОК 20` | Уже в системе | После первой успешной загрузки: диагностика, тихая загрузка, `luksHeaderBackup` на внешний носитель (обязательно в шифрованной редакции), проверка снимков и меню |

> 📌 В UKI-ветке нумерация сознательно оставлена «с дырой»: за `БЛОКОМ 18` идёт `БЛОК 20`, а `БЛОК 19` — аварийный.

💡 **Совет по копированию:** Копируйте команды целиком блоками. Дожидайтесь завершения каждого блока перед переходом к следующему. Блоки с интерактивным финалом (`cryptsetup`, `passwd`) устроены так, что после интерактивной команды в блоке не остаётся исполняемых строк — иначе вставленный хвост ушёл бы в ответ на запрос пароля. Если терминал выдал ошибку — остановитесь, проанализируйте вывод, устраните причину.

## 🔐 Secure Boot: что важно знать до начала

- **GRUB-макеты Secure Boot не поддерживают** — выключите его в прошивке и в настройках ВМ.
- **UKI-макеты** настраивают его в `БЛОКЕ 17`: создаются свои ключи (`sbctl create-keys`), записываются в прошивку с сохранением ключей Microsoft (`sbctl enroll-keys -m` — нужны для подписанного ROM видеокарты, дуал-бута и обновления прошивки), затем подписываются все загрузочные файлы.
- **Порядок критичен:** сначала все пересборки (`mkinitcpio -P`), и только потом подписи. Пересоберёте UKI после подписи — файл станет неподписанным и система с включённым Secure Boot не загрузится. После любой пересборки: `sudo sbctl sign-all && sudo sbctl verify`.
- Если `sbctl enroll-keys` отвечает «Access denied» — зайдите в прошивку и очистите ключи Secure Boot (режим Setup), затем повторите.
- В VirtualBox отдельную галочку дёргать не нужно: пока в UEFI-хранилище нет PK, прошивка в Setup Mode; после записи PK Secure Boot включится сам при следующей загрузке.

## 🖥️ Графика, окружение и пост-настройка

### 🔹 Видеодрайверы — `БЛОК 14`
Четыре сценария, выполнять **только один**:

| Сценарий | Для чего |
|:---|:---|
| **А** | Intel (встроенная графика) |
| **Б** | AMD (Radeon / APU) |
| **В** | NVIDIA, одиночная карта (десктоп/ПК) |
| **Г** | Гибрид: AMD/Intel iGPU + NVIDIA dGPU (рекомендуется для ноутбуков) |

Для NVIDIA критически важны параметр ядра `nvidia-drm.modeset=1`, файл `/etc/modprobe.d/nvidia.conf`, службы `nvidia-suspend/hibernate/resume` и **пересборка initramfs** — иначе Wayland и выход из сна не заработают.

- В **GRUB-ветке** параметр добавляется в `GRUB_CMDLINE_LINUX_DEFAULT` (`/etc/default/grub`), затем `mkinitcpio -P` и `grub-mkconfig -o /boot/grub/grub.cfg`.
- В **UKI-ветке** файла `/etc/default/grub` нет: параметр дописывается в `/etc/kernel/cmdline`, затем пересборка UKI и обязательная повторная подпись (`sbctl sign-all`), включая модули `nvidia*.ko*`.

> ⚠️ Пост-установочный файл (раздел «УСТАНОВКА ВИДЕО-ДРАЙВЕРОВ») — альтернативный путь для тех, кто пропустил `БЛОК 14`: автоподбор через `chwd` (AUR) или ручная установка пакетами (сценарии А–Г), а пункт `1.3` настраивает параметры ядра NVIDIA **для обеих веток макетов** — GRUB (`/etc/default/grub` + `grub-mkconfig`) и UKI (`/etc/kernel/cmdline` + пересборка UKI + подписи модулей `sbctl` при Secure Boot). Ветку определяет `ШАГ 0` раздела. Выберите **один** путь: либо `БЛОК 14`, либо пост-установочный файл, иначе наборы пакетов начнут конфликтовать.

### 🔹 VirtualBox — `БЛОК 15`
Только если установка идёт в ВМ: `virtualbox-guest-utils`, служба `vboxservice`, автозагрузка модулей `vboxguest`/`vboxsf` через `modules-load.d` (по одному модулю на строку), пользователь в группе `vboxusers`.

### 🔹 Окружения рабочего стола — `БЛОК 16`
Готовые команды для **KDE Plasma, GNOME, COSMIC, XFCE4, MATE, Cinnamon, LXQt, LXDE**. Выберите одну среду, скопируйте её вариант, вставьте в терминал (находясь в `chroot`). В конце каждого варианта стоит `exit` — выход из `chroot` произойдёт автоматически.

### 🔹 Пост-установочный чек-лист — `POST-INSTALL Arch Linux.txt`
Выполняется **строго после перезагрузки** в новую систему, от обычного пользователя с `sudo`. Разделы помечены приоритетами `[ОБЯЗАТЕЛЬНО]` / `[ОПЦИОНАЛЬНО]`:

- `base-devel`, сборка `yay` (AUR-хелпер), `fstrim.timer`
- настройка `nano` (`/etc/nanorc` и `~/.nanorc`)
- Zsh + Oh My Zsh, плагины, `eza`, `hyfetch`; тема GRUB `arch-leap` (AUR)
- звук: ALSA/`amixer`/PipeWire, EasyEffects с пресетами
- видеодрайверы через `chwd` (AUR) и диагностика графики (`glxinfo`, `vulkaninfo`, `vainfo`, `glxgears`, `vkcube`, `glmark2`)
- VirtualBox (хостовая часть)
- игры: Wine/Proton/Lux-Wine и компоненты `winetricks`, MangoHud + VkBasalt, Steam, `protonup`
- межсетевой экран **UFW** и правила для сетевых устройств (mDNS, SSDP, LLMNR, IPP, RAW-печать, SANE)
- укрепление: `sysctl`-параметры и пароль суперпользователя GRUB (PBKDF2)
- менеджер паролей Bitwarden: этапы 0–7 (свой сервер на Docker или облако, клиент, Server URL, синхронизация с браузерами, Wayland/биометрия, импорт паролей)
- энергосбережение TLP: три части (TLPUI, ручная правка `/etc/tlp.conf`, автоматизация через `sed`) и корректный сброс настроек
- приложения: `doublecmd-qt6`, `vlc`, `hardinfo2`

> 📌 **Не дублируйте настройку.** `snapper`, `snap-pac`, `btrfs-assistant`, `zram-generator`, `earlyoom` и `nftables` настраиваются в `БЛОКЕ 13` макетов — в пост-установочном файле их нет. Файрвол там другой: перед включением UFW скрипт явно останавливает и отключает `nftables`, чтобы два фильтра пакетов не конфликтовали.

## 🆘 Отладка

| Симптом | Вероятная причина | Решение |
|:---|:---|:---|
| Чёрный экран / зависание при загрузке | Не собран initramfs или параметры ядра не дошли | `БЛОК 12`: `mkinitcpio -P`; GRUB-ветка — `grub-mkconfig -o /boot/grub/grub.cfg`; UKI-ветка — проверить `/etc/kernel/cmdline` и пересобрать UKI. Первая загрузка намеренно идёт без `quiet splash` |
| Не открывается LUKS при загрузке | Неверные параметры ядра или состав хуков | GRUB-ветка: `rd.luks.name=<UUID>=cryptlvm rd.luks.options=discard` и хуки `… block sd-encrypt lvm2 resume …`. `rd.lvm.lv=…` — синтаксис dracut, в Arch с systemd-инитрамфсом не используется |
| GRUB не видит систему | Ошибка в `--efi-directory` или нет раздела BIOS Boot | UEFI: `grub-install --target=x86_64-efi --efi-directory=/boot`. BIOS: обязателен раздел `ef02` |
| `Access denied` при включённом Secure Boot | UKI/ядро не подписаны после пересборки | Только UKI-макеты: `sudo sbctl sign-all && sudo sbctl verify`. В GRUB-макетах Secure Boot не настраивается — выключите его |
| В меню нет пунктов снимков Btrfs | Не работает интеграция снимков | GRUB-ветка: `systemctl status grub-btrfsd`, настройки в `/etc/default/grub-btrfs/config`. UKI-ветка: `БЛОК 13A`, а после отката — `БЛОК 13B` |
| Не появляется заставка plymouth | Нет `plymouthd.conf` или initramfs собран раньше него | Файл `/etc/plymouth/plymouthd.conf` (`Theme=…`, `ShowDelay=0`) создаётся **до** `mkinitcpio -P`; в VirtualBox нет таблицы BGRT — будет только анимация, это норма |
| `unrecognized filesystem` при монтировании | Ошибка в `/etc/fstab` | Используйте `genfstab -U /mnt`; для Btrfs должно быть `subvol=@` |
| Wayland не работает (NVIDIA) | Отключён KMS | `nvidia-drm.modeset=1` (GRUB: в `/etc/default/grub`; UKI: в `/etc/kernel/cmdline`) + пересборка initramfs/UKI |
| Система ушла в emergency mode (LUKS2 + UKI) | Повреждён заголовок LUKS или сменились UUID | `БЛОК 19` аварийного восстановления с live-ISO; при наличии копии заголовка — `cryptsetup luksHeaderRestore` |

### 📚 Путь самостоятельного изучения
Установка Arch Linux — это не финиш, а старт. Чтобы превратить этот проект в полноценный образовательный опыт:
1. 📖 Читайте [Arch Wiki](https://wiki.archlinux.org/) — это эталонный источник знаний.
2. 🔍 Используйте `man <команда>` и `journalctl -p 3 -xb` для анализа ошибок.
3. 🤝 Задавайте вопросы на [форуме Arch Linux](https://bbs.archlinux.org/) или в русскоязычных Telegram-чатах, прикладывая вывод `journalctl` и `lsblk`.
4. 🔄 Не бойтесь ломать систему. С `BTRFS + Snapper` вы всегда можете откатиться к рабочему состоянию через меню загрузчика или Live-USB.

## 🤝 Как предложить правку

1. Шапка каждого макета содержит разделы «Исправленные дефекты» и «Ключевые решения» — при содержательной правке добавьте туда пункт, чтобы история редакции не терялась.
2. Цветные окна проверок выровнены по **74 символа** между `║…║` (76 колонок с рамкой). Сохраняйте ширину: окна рисуются в терминале, а не в браузере.
3. Внутри рамок не используются эмодзи и `dialog` (он читает клавиши из stdin и «съедает» хвост вставленного блока).
4. Макеты **не являются скриптами**: их копируют блоками и выполняют вручную. Не добавляйте команд после интерактивных (`passwd`, `cryptsetup`) — хвост уйдёт в ответ на запрос пароля.
5. Одна и та же правка обычно нужна в нескольких редакциях семейства: проверьте парные файлы (`UEFI`/`BIOS`, GRUB/UKI).

> 🐧 **Arch Linux — это система, которая учит вас тому, как работает Linux.** Этот макет убирает рутину набора команд, но оставляет полный контроль и прозрачность процесса. Удачи в освоении!
